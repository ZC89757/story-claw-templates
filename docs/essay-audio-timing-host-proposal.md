# 议论文时间轴偏移：待批准的主项目修正

2026-10-17，用当前 Story Claw 代码为本集 58 段全文生成旁白后发现：

- 各组 MP3 容器时长之和：843.456 秒。
- 拼接后 WAV 的 ffprobe 实际时长：840.672018 秒。
- 字级时间轴最后一个字结束：843.038 秒，超出音轨 2.365982 秒。
- 时间轴文字去除空白后与原文逐字一致；问题是累计时间偏移。

`runner/render.ts` 的 `prepareEssayAudioTimeline` 用 `ttsResults[].duration` 累计全局字级及字幕时间；这些组时长来自 `getMediaDuration`，包含 MP3 编码头尾填充。最终 WAV 拼接时解码丢弃了填充，累计边界因此不同。

建议只修议论文这一步：在构建全局字级时间轴和字幕前，按实际解码的 PCM 样本量测每组可播放长度，以此累计偏移；本地时间仍由真实 TTS 字级数据决定，并夹在本段有效区间。旁白音频、文稿、已审核 HTML 和模板参数均不改。不做整条音轨拉伸，也不重新付费合成已有配音。

需要修改主项目 `runner/render.ts` 并加定向验证，获批前不执行。验证应覆盖：多段 MP3 填充不累计成偏移、末字不超出音频、字幕与字级时间使用同一组边界、文字逐字一致。模板包不负责修复宿主时间轴。
